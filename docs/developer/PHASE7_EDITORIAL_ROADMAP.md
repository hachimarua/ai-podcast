## 目的

現行の安定した毎朝配信を維持しながら、次の2点を改善する。

1. ニュースを一言で終わらせず、重要性・背景・制約まで伝える。
2. 既に実践済みの初心者向けTipsを減らし、「知らなかった、試したい」を増やす。

## 固定する前提

- 配信は**1日1本**のまま。5分版と10分版を同日に2本配信しない。
- 通常回は `Daily Brief`（4〜6分）。
- 週1回は `AI実装ラボ`へ置き換える。目標は8〜12分、話速は `+10%`、品質ゲートの最低尺は7分30秒、曜日は日曜日。
- 共有記憶層は非公開の正本とし、公開リポジトリへ直接コピーしない。
- 小さな実装はサブ担当・軽量モデルへ委譲してよいが、個人情報境界と公開判定はCodexが最終確認する。
- Codexは毎日の監査経路には置かず、節目レビューと高リスク変更時だけユーザー確認後に入る。

## Phase 7: 番組用編集プロフィール

共有記憶層から、番組に必要な公開可能情報だけを抽出する。

- 含める: AI習熟度、利用可能なツール群、既に実践済みの初歩的Tips、関心領域
- 含めない: 年齢、居住地、医療情報、ローカルパス、APIキー、個別プロジェクトの私的情報
- ホワイトリスト方式で生成し、差分を人間が承認してから反映する
- 古いカスタム指示より共有記憶層を優先し、現在の対象像を「AIで仕組みを構築・運用している実践者」とする

完了条件:

- 個人情報を含まない番組用プロフィールが生成される
- 禁止項目の混入をテストで検出できる
- 現行Daily版が従来どおり生成できる

## Phase 8: 2つの番組形式

台本生成を `daily` と `lab` の2形式へ分ける。

### Daily Brief（4〜6分）

- 主ニュース1件を深掘り
- 2件目は十分な説明時間がある場合だけ採用
- Tipsは必須にせず、価値がなければ注意点・観察ポイントへ置き換える

### AI実装ラボ（8〜12分）

- 1テーマを複数ソースで検証
- 公式ドキュメントや公式リリースノートを実装根拠に使う
- 既存ツールを使った具体的手順、期待結果、適用しない条件まで扱う

完了条件:

- 設定だけで `daily` / `lab` を切り替えられる
- 形式別の文字量・音声時間・品質閾値が独立している
- タイトルと概要欄に、その回のテーマと形式が表示される
- 1日1本と同日再実行の安全性を維持する

### Phase 8 実装状況（2026-07-14）

- `episode_formats.py` と `config/episode_formats.json` に閉じた形式設定を追加した。Dailyは4〜6分、Labの目標は8〜12分で、文字量と音声品質閾値を独立させた。ユーザー試聴後、Labの話速を `+10%`、最低許容尺を7分30秒とした。
- 形式は実行開始時に1回だけ決め、台本生成、文字量検査、音声検査、Manifest、RSSへ同じ設定を渡す。
- Dailyの2件目は主ニュースとの共通テーマを確認できる場合だけ採用し、Tipsは任意とした。
- Labは、同一の復習テーマ、異なるURL・配信元2件以上、信頼済み設定上の公式ソース1件以上を必須とする。不足時は自動予定回のみDailyへ安全に戻す。
- 同日再実行は当日Manifestを過去回比較から除外しつつ直近3回を保持し、同日のNotion復習回数を再加算しない。
- Manifest/RSS/Actionsログ/品質レポートは閉じた公開用項目だけを保存し、Notion原文・生ID、編集プロフィール本文、モデル生成の自由記述QAを公開しない。既存品質レポートも同じ境界へ移行した。
- 現在は全96件のテストが成功している。
- `weekly_lab.enabled` はユーザー承認後に `true` とし、日曜日だけLabへ切り替える。

## Phase 9: Tips高度化と編集QA

- Tipsは「具体的操作・期待結果・使わない条件・根拠」が揃う場合だけ採用
- 過去14回のテーマとTipsを参照し、重複と初歩化を検出
- 編集QAは二層に分ける。
  - 公開前ゲート: 固有名詞、日付、価格、バージョン、数値、機能可否、引用、URLを採用ソースへ照合し、根拠へ到達できない主張は削除または不確実性を明示する。
  - シャドー評価: 新規性、情報密度、実践可能性、対話の自然さなどの主観的品質は記録・改善提案に使い、それだけで公開停止しない。
- 編集QAへ次の5項目を追加
  - 新規性
  - 情報密度
  - 実践可能性
  - 根拠性
  - 非重複性
- 初期はシャドー評価とし、編集QAだけで配信を止めない

完了条件:

- 初心者向け・重複Tipsをfixtureで除外できる
- 根拠のない操作手順を公開しない
- Episode Manifestから採用理由と編集QAを確認できる

## Phase 10: 安全導入と2週間パイロット

1. `lab` をローカルまたは非公開artifactで2回生成する
2. RSSを変更せず、内容・尺・音声品質を確認する
3. 問題がなければ週1回だけ公開する
4. Daily Briefを毎日、AI実装ラボを週1回で2週間運用する

評価項目:

- 「知らなかった」: 週3回以上
- 「実際に試した」: 週1回以上
- 一言だけで終わる採用ニュース: 原則ゼロ
- Daily版の配信失敗・重複配信: ゼロ
- ローカルで追加の追跡基盤を増やさず取得できる場合だけ、30秒到達と最終区間到達を補助指標にする。

評価入力はApple Watchの文字盤へボタンを追加せず、既存のSiri長押しから音声ショートカットで任意に行う。メールや自由記述は要求しない。無入力は低評価とみなさず、評価データ不足として扱う。

2週間後に、尺、Labの曜日、ニュース件数、Tips条件を再判断する。
